# Backtest Results Library

This directory maintains a complete trading journal of all backtests performed on the Helix algorithmic trading system. Each backtest captures signal performance, regime analysis, SHAP feature importance, and cost sensitivity metrics.

## Files

### `backtest_log.csv`
**Master trading journal** — one row per backtest run per pair.

**Columns:**
- `Date`: Backtest execution date (YYYY-MM-DD)
- `Pair`: Currency pair (EURUSD, GBPUSD, AUDUSD, etc.)
- `Timeframe`: Bar frequency (1H, 4H, 1D, etc.)
- `Data_Period_Months`: Length of historical data window
- `Bars_Available`: Total OHLCV bars pulled from data source
- `Bars_OOS`: Out-of-sample test bars (after warmup)
- `Config_Train_Window`: Training window size (bars)
- `Config_Test_Window`: Test window size (bars)
- `Config_Purge_Gap`: Purge gap between train and test (label leakage prevention)
- `Config_Step`: Step size for rolling window
- `Num_WF_Windows`: Total walk-forward windows executed
- `Num_Trades`: Total trades generated by the ensemble
- `Trades_Per_Bar_Pct`: Trade frequency as % of OOS bars
- `Gross_Sharpe`: Sharpe ratio before spread costs
- `Net_Sharpe`: Sharpe ratio after spread costs (PRIMARY METRIC)
- `Max_Drawdown_Pct`: Peak-to-trough drawdown (%)
- `Win_Rate_Pct`: Percentage of profitable trades
- `Profit_Factor`: Sum of winning trades / |Sum of losing trades|
- `Total_Return_Pct`: Total P&L as % of starting capital
- `Base_Spread_Pips`: Transaction cost assumption (pips)
- `Stable_Features`: SHAP-identified features in top-5 (>50% of windows)
- `Regime_Trending_Pct`: % of bars classified as Trending regime
- `Regime_MeanRev_Pct`: % of bars classified as Mean-Reverting regime
- `Regime_Volatile_Pct`: % of bars classified as Volatile regime
- `Notes`: Configuration changes, insights, iteration notes

## How to Add a New Backtest Row

### Step 1: Run the Validation Script
```bash
cd /home/user/Desktop/Projects/BANDD/helix
PYTHONPATH=. PYTHONUNBUFFERED=1 .venv/bin/python -u scripts/validate_pipeline.py \
  --pairs EURUSD GBPUSD \
  --months 24
```

### Step 2: Capture Output Metrics
The script prints formatted tables with all metrics. Extract:
- Gross Sharpe, Net Sharpe, Max Drawdown, Win Rate, Profit Factor, Total Return
- Number of trades
- Stable features (SHAP analysis)
- Regime distribution

### Step 3: Add Row to CSV
Open `backtest_log.csv` and append a new row with the date, pair, and metrics. Use this format:

```
2026-03-23,EURUSD,1H,18,9095,8064,756,21,5,21,384,1790,22.2,-3.637,-5.581,-86.4,35.4,0.805,-85.1,0.00012,"mom_1bar,mom_5bar,mom_10bar,mom_22bar,mom_63bar",80.3,12.9,6.8,Iteration 2: Widened thresholds to 0.60/0.40
```

## How to Interpret Results

### Key Metrics Priority (in order)

1. **Net Sharpe** (after spread costs)
   - \> 0.5: Potentially viable alpha
   - 0.0 to 0.5: Marginal, needs validation
   - < 0.0: **FAIL** — strategy destroys capital

2. **Profit Factor**
   - \> 1.5: Strong
   - 1.0 to 1.5: Acceptable
   - < 1.0: **FAIL** — more losses than wins

3. **Max Drawdown**
   - < 20%: Acceptable
   - 20-50%: Risky
   - \> 50%: **FAIL** — catastrophic for live trading

4. **Win Rate**
   - \> 55%: Good
   - 45-55%: Marginal
   - < 45%: Signal may be inverted

5. **Trades Per Bar (%)**
   - < 5%: Healthy (high-quality signals)
   - 5-20%: Acceptable
   - \> 20%: Overtrading (too many low-confidence signals)

## Analysis Examples

### Cost Sensitivity Tracking
The `Base_Spread_Pips` column tracks the transaction cost assumption. By comparing rows with different spread assumptions, you can see how fragile the edge is.

**Example:** If `Base_Spread_Pips=0.00012` gives Sharpe -5.5 and `Base_Spread_Pips=0.00006` gives Sharpe -2.8, the strategy has weak edge.

### Feature Stability Monitoring
The `Stable_Features` column shows which features SHAP ranks as consistently important. Over time, this reveals:
- Which tiers of features matter (Momentum, Volatility, Session, Cross-Asset, Tick Volume)
- Whether the model is converging to a consistent feature set or chasing noise

**Example:** If only momentum features appear consistently, other feature tiers may be unnecessary noise.

### Regime Distribution Calibration
The regime percentages reveal market composition during backtest period. Use this to:
- Understand which regimes your strategy trades in
- Design regime-conditional entry/exit (only trade in certain regimes)

**Example:** If Trending is 80% of the time, ensure the strategy performs well in Trending regime.

## Iteration Protocol

Use this checklist for each backtest iteration:

- [ ] Document configuration changes in the `Notes` column
- [ ] Record date of backtest run
- [ ] Capture all metrics (Sharpe, Drawdown, Win Rate, Profit Factor)
- [ ] Save a copy of the detailed validation report (PDF or Markdown)
- [ ] Compare new row to previous rows — identify improvements or regressions
- [ ] If Sharpe improved, commit the change and prepare next iteration
- [ ] If Sharpe worsened, revert change and try different approach
- [ ] Track the commit hash for reproducibility
